# Contributing

Contributions are welcome through focused issues and pull requests. Version 3 deliberately has one owner for each product invariant: `src/coordinator/install`, `state`, `routing`, `dashboard`, and thin `cli` adapters. Preserve those boundaries and the no-project-footprint contract.

## Development

Use Python 3.11 or newer. The runtime has no third-party dependencies.

Install the pinned development-only linter in a disposable environment:

```sh
python3 -m pip install ruff==0.16.2
```

Run the repository checks:

```sh
python3 -m unittest discover -s tests -v
python3 -m compileall -q src skill/scripts tools tests
ruff check --no-cache src skill/scripts tools tests
```

Build twice into separate empty temporary directories and compare all assets when changing package content or build logic. Run the independent verifier against each build. Installer tests must use an isolated home and the public `--source` behavior; do not add a hidden installation bypass.

Add the smallest decisive test for a changed public contract. Avoid duplicate cross-layer assertions, broad fixture frameworks, generated bytecode, credentials, release outputs, or user-specific paths in commits.

## Pull requests

Describe the observable change, owner, compatibility impact, and exact checks run. Breaking behavior requires a major-version decision. Security-sensitive findings should follow [SECURITY.md](SECURITY.md), not a public issue.

## Maintainer release

Configure the repository before a release, then read the effective settings back instead of relying on intended values:

- Keep the repository public with `main` as the default branch. Enable Actions with SHA-pinned actions and read-only default workflow permissions.
- Protect `main` from bypass and require `Lint / Python 3.11` plus all twelve `<os> / Python <version>` CI checks before merge.
- Protect the `trusted-agentic-e2e` environment with approval and a `main` deployment policy. Store `OPENAI_API_KEY` only as an environment secret; the workflow may expose it only through the Codex action's `openai-api-key` input, never through workflow, job, or ordinary step environment variables.
- Protect the `release` environment with approval and an exact `v3.0.0` tag deployment policy. Its publish job is the only job granted `contents: write`.

Enter the key interactively so its value does not appear in the command or shell history:

```sh
gh secret set OPENAI_API_KEY --env trusted-agentic-e2e
```

Use an administrator-authenticated GitHub CLI for this read-only audit; secret endpoints return names, not values:

```sh
gh repo view --json visibility,defaultBranchRef,mergeCommitAllowed,rebaseMergeAllowed,squashMergeAllowed
gh api 'repos/{owner}/{repo}/actions/permissions'
gh api 'repos/{owner}/{repo}/actions/permissions/workflow'
gh api 'repos/{owner}/{repo}/rules/branches/main'
gh api 'repos/{owner}/{repo}/rulesets' --jq '.[].id' |
while read -r ruleset; do gh api "repos/{owner}/{repo}/rulesets/$ruleset"; done
for environment in trusted-agentic-e2e release; do
  gh api "repos/{owner}/{repo}/environments/$environment"
  gh api "repos/{owner}/{repo}/environments/$environment/deployment-branch-policies"
done
gh api 'repos/{owner}/{repo}/environments/trusted-agentic-e2e/secrets' --jq '.secrets[].name'
```

Release in this order, without an administrative bypass:

1. Make every required pull-request check pass, merge through the protected branch, fetch `main`, and record the exact merged commit.

   ```sh
   gh pr checks --required --watch
   gh pr merge
   git fetch origin main
   release_commit=$(gh pr view --json mergeCommit --jq '.mergeCommit.oid')
   test -n "$release_commit"
   git merge-base --is-ancestor "$release_commit" origin/main
   ```

2. Wait for `Trusted agentic E2E` on that exact `main` commit to pass.

   ```sh
   e2e_run=$(gh run list --workflow trusted-agentic-e2e.yml --branch main --commit "$release_commit" --limit 1 --json databaseId --jq '.[0].databaseId')
   test -n "$e2e_run"
   gh run watch "$e2e_run" --exit-status
   ```

3. Create and push annotated tag `v3.0.0` at that commit only after the E2E succeeds.

   ```sh
   git tag -a v3.0.0 "$release_commit" -m "v3.0.0"
   git push origin refs/tags/v3.0.0
   ```

4. Watch `Release v3.0.0` for the tagged commit, then read the public release back.

   ```sh
   release_run=$(gh run list --workflow release.yml --commit "$release_commit" --limit 1 --json databaseId --jq '.[0].databaseId')
   test -n "$release_run"
   gh run watch "$release_run" --exit-status
   gh release view v3.0.0 --json tagName,targetCommitish,isDraft,isPrerelease,assets,url
   ```

The release is complete only when its anonymous Linux, macOS, and Windows verification jobs pass. They must download exactly `coordinator-3.0.0.zip`, `coordinator-latest.zip`, `install.py`, `manifest.json`, and `SHA256SUMS`; verify checksums and package/root manifest identity; require manifest version `3.0.0`; and bind `manifest.source_commit` to the anonymously resolved, peeled public `v3.0.0` tag commit before installation.

If CI or the trusted E2E fails, do not tag; fix through another pull request. If tagging or publication fails, inspect the remote tag and release before retrying:

```sh
git ls-remote origin refs/tags/v3.0.0 'refs/tags/v3.0.0^{}'
gh release view v3.0.0 --json tagName,isDraft,isPrerelease,assets,url
```

Retry an unchanged tag only for a transient workflow or settings failure before publication. Never force-move or delete a public tag, overwrite a release, or upload assets with `--clobber`. Fix a code or asset defect forward with the next SemVer patch and repeat the full gate sequence.
